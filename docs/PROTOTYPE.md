# Разбор прототипа «МЭР · Екатеринбург — Живой город»

Исходники лежат без изменений в [`public/prototype/`](../public/prototype/) и публикуются
вместе с игрой по адресу `<сайт>/prototype/`.

## Что это

Мобильная (вертикальная, ~540 px) браузерная игра-сессия на 12 игровых дней в реальном времени.
Игрок — мэр центра Екатеринбурга: устраняет городские аварии бригадами, следит за казной,
настроением жителей и пробками, строит скверы и магазины. В конце — «выборы»: победа, если
поддержка ≥ 50, казна ≥ 0 и пробки ≤ 9.

Техника: один `index.html`, `style.css` (~13 КБ), `game.js` (~31 КБ минифицированного
ванильного JS, без зависимостей), картинка карты `assets/center_map.webp` 802×1240.

## Игровые системы

### Время

- `CONFIG.secondsPerDay = 52` — один игровой день длится 52 с на скорости ×1.
- Скорости: пауза, ×1, ×3, ×6. Открытие любой панели ставит игру на паузу.
- Состояние времени — одно число `elapsed` (дни, дробное). Часы суток = дробная часть × 24.
- Цикл: `requestAnimationFrame` → `advance(dt)` → `finishRepairs()` + `daily(d)` на смене дня.
- Длительность партии `CONFIG.days = 12`.

### Экономика (млрд ₽)

| Параметр          | Значение                                    |
| ----------------- | ------------------------------------------- |
| Стартовая казна   | 13                                          |
| Базовые налоги    | +4,2 / день                                 |
| Содержание города | −2,5 / день                                 |
| Зарплаты бригад   | −0,45…0,65 / день за бригаду                |
| Здания            | магазин: +2,2 налога, −0,25 содержание      |
| Ремонт аварии     | базовая цена + 0,45 за каждый день ожидания |

Баланс начисляется раз в игровой день. Казна < 0 → −3 к настроению.

### Бригады (`STAFF`)

| Тип       | Название      | Машина | Найм | Зарплата | Время работы (дни) |
| --------- | ------------- | ------ | ---- | -------- | ------------------ |
| `utility` | Ремонтники    | 🚚     | 2,2  | 0,55     | 0,33               |
| `transit` | Путейцы       | 🚐     | 2,5  | 0,65     | 0,42               |
| `clean`   | Коммунальщики | 🚛     | 1,8  | 0,45     | 0,27               |

Лимит — 4 бригады каждого типа. Старт: 1 ремонтник + 1 путеец.
Выезд: дорога 0,22 дня → работа → возврат 0,17 дня. Бригада движется по заранее заданным
ломаным (`crewPath`) от депо (`DEPOTS`), без реального поиска пути.

### Аварии (`INCIDENT_TYPES`)

| Тип        | Название        | Служба  | Цена | Штраф к настроению/день |
| ---------- | --------------- | ------- | ---- | ----------------------- |
| `water`    | Прорвало трубу  | utility | 2,0  | 2,3                     |
| `road`     | Разбитая дорога | utility | 2,4  | 1,7                     |
| `tram`     | Сломались пути  | transit | 2,3  | 2,2                     |
| `trash`    | Мусор во дворах | clean   | 1,4  | 1,5                     |
| `heritage` | Осыпается фасад | utility | 2,6  | 1,5                     |
| `park`     | Заросший сквер  | clean   | 1,5  | 1,2                     |

- Аварии появляются по **жёсткому сценарию** `EVENTS` (по одной на дни 2–10, максимум 5 открытых).
- Штраф от аварии, к которой уже едет бригада, умножается на 0,28.
- Ремонт: настроение +5 (вода) или +3,7; дорога/трамвай снижают базовую загруженность на 1,25.

### Настроение жителей

- Одно число `mood` 0…100 (старт 69), отображается как 30 смайликов 😊/😐/😡.
- Ежедневно: `+1,7 − сумма штрафов`, ограничено диапазоном [−6; +2].
- Сквер +8, магазин +1 при открытии.

### Пробки

- `trafficBase` 1…10, ежедневно растёт на 0,24 (+0,43 при открытых авариях дорог/путей).
- Итоговый балл = база + 0,9 × (аварии дорог/путей) + синусоида времени суток.
- 8 условных отрезков улиц (`TRAFFIC_LINES`: пр. Ленина, ул. Малышева, мост и др.) красятся
  по уровню. Это стилизация, не данные о реальных пробках.

### Строительство

3 фиксированных участка (`PLOTS`). Сквер (3 млрд, −0,3 к пробкам, +8 настроения) и
магазин (5 млрд, +2,2 налога/день, +1 к пробкам). Стройка 0,7–1,05 дня.

### Обучение

Линейный сценарий `step` 0…4: починить воду → посмотреть выезд → нанять коммунальщиков и
убрать мусор → построить магазин → свободная игра. Отображается в плашке задания.

### Сохранение

`localStorage` под ключом `ekb_workers_traffic_v1`, автосохранение каждые 3,5 с и при уходе со
страницы; после загрузки игра стоит на паузе.

## Карта

`center_map.webp` — сгенерированная изометрическая иллюстрация центра: Городской пруд,
Плотинка, Мэрия, площадь 1905 года, пр. Ленина, ул. Малышева, башня «Исеть», «Высоцкий»,
Исторический сквер, жёлтые участки под застройку. Объекты привязаны к ней координатами
в процентах (инциденты, участки, депо) или в пикселях 802×1240 (линии пробок, транспорт).
Геометрия иллюстративная, а не геоданные.

## Что стоит взять

- Ядро цикла «авария → выбор бригады → машина едет → ремонт → эффект» — наглядно и понятно.
- Бюджет с ежедневным балансом и видимыми статьями доходов/расходов.
- Визуализация настроения как «толпы» смайликов и раскраска улиц по загруженности.
- Мобильная вёрстка: нижний лист (bottom sheet), плашка текущего задания, кнопки скорости.
- Табличные описания (`STAFF`, `INCIDENT_TYPES`, `BUILDINGS`) — хорошая основа для data-driven
  баланса.

## Ограничения и техдолг

- Всё в одном файле, логика смешана с DOM; состояние мутируется напрямую; не тестируется.
- `Math.random()` в эффектах → симуляцию нельзя воспроизвести.
- Аварии по сценарию, а не процедурно; 3 участка; один район.
- Маршруты бригад — ручные ломаные под каждую пару «тип бригады × тип аварии».
- Ошибка в `pOnRoute`: координата `y` интерполируется как `a.y + b.y·v` вместо
  `a.y + (b.y − a.y)·v` — машины/трамвай уезжают вниз по экрану.
- `hire()` содержит пустую ветку `if (type==='clean' && s.step===2) s.step=2`.
- README упоминает автономный `mer_ekb_brigades.html`, которого нет в архиве.
- Выборы — только итоговая проверка трёх порогов; кандидатов, кампании и районов нет.
