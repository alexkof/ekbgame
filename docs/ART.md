# Рисунки зданий: методика

Здания на карте показываются **рисунками**, а 3D-модели остаются промежуточным шагом. Рисунок
делает художник или генератор изображений (ChatGPT и т. п.) поверх **каркаса** — модели,
отрисованной в проекции карты. Поэтому рисунок встаёт на карту пиксель в пиксель, без ручной
подгонки, а все здания видны с одной камеры и при одном свете.

Инструкция для того, кто рисует, и список зданий — [art/README.md](../art/README.md).

## Конвейер

```
OSM ──osm_tool.py building──► модель ──art.py prepare──► каркас + запрос ──ChatGPT──► рисунок
 контур, части,          models/<id>.json            art/<id>/guide.png        art/<id>/drawn/*.png
 высоты, крыша           (+ доводка по фото)          art/<id>/README.md               │
                                                                                       ▼
                       карта ◄── models/<id>/art.webp + поле "art" ◄──art.py import── (CI)
```

1. **Модель из OSM** — `python scripts/map/osm_tool.py building w123 --id <id> --kind …`
   (`scripts/map/buildings.py`): контур здания или его части (`building:part`), высоты
   (`height`, `min_height`, этажность), крыша (`roof:shape`: плоская, двускатная, вальмовая,
   шатёр, купол, луковица), цвета (`building:colour`, `roof:colour`, материал). Заодно
   добавляется объект карты: участок (контур с отступом 4 м), точка привязки, адрес,
   описание. Правила — «Простые 3D-здания» OSM; без высоты — этажи по 3,2 м (до 1940 года —
   3,9 м), без высоты крыши — уклон по ширине здания, но конёк не выше 4,5 м.
2. **Доводка модели по фото** (вручную или Claude). Модель задаёт силуэт, по которому потом
   вырезается фон, поэтому в ней должно быть всё, что определяет силуэт: башни, купола,
   шпили, высокие крыши; цвета — примерно как в жизни (генератор от них отталкивается). Мелкий
   декор не нужен — его рисует генератор.
3. **Каркас и запрос** — `python scripts/art/art.py prepare <id>`:
   - `guide.png` — модель в цвете на белом фоне; запасные варианты — `guide-lines.png`
     (контуры) и `guide-clay.png` (глина); `mask.png` — силуэт; `frame.json` — кадр: размер,
     пикселей на метр, пиксель точки привязки, отпечаток геометрии модели;
   - холст — сразу одного из размеров ChatGPT (1024×1024, 1536×1024, 1024×1536), модель по
     центру с полями 7 %, поэтому ответ генератора не нужно обрезать;
   - `info.json` — заметки о здании (входят в запрос), ссылки на фото (Викисклад и Википедия —
     по Викиданным из тегов OSM, панорамы Яндекса и Google, PastVu, поиск), теги OSM;
   - `README.md` — каркас, готовый запрос и ссылки. GitHub показывает его в папке здания,
     у запроса есть кнопка «скопировать».
4. **Рисунок** — в ChatGPT: каркас первым, затем 1–3 фото, запрос. Готовую картинку —
   в `art/<id>/drawn/` (на GitHub: Add file → Upload files).
5. **Импорт** — `python scripts/art/art.py import <id>` (`scripts/art/art_import.py`); при
   загрузке в `main` его делает GitHub Actions (`.github/workflows/art.yml`) и сам
   публикует сайт:
   - рисунок вписывается в размер каркаса;
   - сдвиг, масштаб и небольшой перекос (генераторы «гуляют» на несколько процентов) находятся
     методом ECC — сначала по силуэтам, потом по контурам; неправдоподобный результат
     (масштаб вне 0,8…1,25, перекос, сдвиг больше 15 % кадра) отбрасывается;
   - фон вырезается **гибридно**: внутри силуэта модели рисунок сохраняется целиком; у края
     силуэта и за ним (до 5 % ширины кадра) — только нарисованное не на фоне и связанное со
     зданием. Фон — прозрачность PNG или белое, соединённое с краем картинки. Так остаются
     башенки и шпили, которых нет в модели, и пропадают случайные предметы вокруг;
   - поля обрезаются, картинка уменьшается до 16 пикселей на метр (больше на карте не нужно:
     зум 6 × экран 2x × укрупнение до 1,3), сохраняется в WebP;
   - в модель пишется поле `art`; `art/<id>/check.jpg` — проверка: рисунок на клетке,
     красным — контуры каркаса.

На карту ставится последний добавленный рисунок (по истории git). Вернуть прежний —
`"use": "drawn/<файл>"` в `info.json`.

## Модель и рисунок

Пример (значения в `art` пишет `art.py import`):

```json
{
  "id": "sevastyanov-house",
  "name": "Дом Севастьянова",
  "parts": [{ "type": "prism", "outline": ["…"], "z": [0, 16.2], "hip": 4.5 }],
  "art": {
    "image": "sevastyanov-house/art.webp",
    "size": [784, 780],
    "origin": [370.2, 489.5],
    "ppm": 14.691,
    "geometry": "2101cd024e3d823c",
    "source": "art/sevastyanov-house/drawn/01.png"
  }
}
```

- Если у модели есть `art` и картинка загрузилась, в цвете рисуется она, а не примитивы
  (`drawModel`). Каркасы (`clay`, `lines`, `normals`) — всегда по примитивам.
- Тень, выбор детализации (значок вместо мелкого здания), сортировка «с севера на юг» и
  выбор касанием работают как раньше: тень и габарит — по модели, касание — по пикселям
  спрайта.
- Пока картинки грузятся (и если рисунка нет), здание видно примитивами: игра открывается
  сразу, рисунки догружаются (`loadModelImages` → `MapView.refreshModels`).
- `geometry` — отпечаток геометрии модели (`artGeometryKey`: контуры, высоты, крыши, без
  цветов и фасадов). Если модель изменилась, тесты требуют новый каркас (`art.py prepare`) и
  новый импорт: старый рисунок совмещается с новым каркасом (`art.py import <id>`) или
  рисуется заново. Тот же отпечаток считает `art.py` (Python), чтобы видеть устаревшие
  каркасы (`art.py status`).

Что добавлено в модели ради зданий из OSM: `holes` (дворы — стены двора рисуются, у крыши
дыры), `gable` (двускатная крыша), `hip` над любым контуром (у четырёхугольника — конёк, у
других — скаты к плоской вершине, контуру, сдвинутому внутрь).

## Запрос

Общая часть — в `scripts/art/art.py` (`prompt`), стиль — в [`art/style.txt`](../art/style.txt),
особенности здания — `notes` в `art/<id>/info.json`. Главное в запросе:

- сохранить кадр каркаса: камеру, положение, размер и силуэт; вертикали — с тем же наклоном
  вправо, параллельные — параллельны, без перспективы;
- какие стены видны (считается по модели: камера с юга, видны южные и западные) — и что на
  фото может быть другая сторона здания;
- свет с юго-юго-востока (как у моделей и теней на карте);
- белый фон, без земли, теней, деревьев, людей, машин, подписей;
- единый стиль для всех зданий; удачный рисунок можно прикладывать как образец стиля.

## Почему так

| Вопрос               | Решение                                                         | Почему                                                                                                                  |
| -------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Чем задать геометрию | Каркас из модели в проекции карты                               | Генератор не умеет нашу косоугольную проекцию по словам; по картинке он держит кадр с точностью до нескольких процентов |
| Откуда модель        | OSM + доводка по фото                                           | Контуры и этажность в OSM есть почти у всех зданий центра; силуэтные детали (башни, купола) приходится добавлять руками |
| Как вырезать фон     | Гибрид: силуэт модели + фон рисунка                             | Только по силуэту — срезаются башенки; только по фону — белые фасады сливаются с белым фоном                            |
| Как совместить       | ECC по силуэтам и контурам, с проверкой правдоподобия           | Цвета рисунка и каркаса разные, а края совпадают; аффинного преобразования хватает для «гуляния» генератора             |
| Кто ставит рисунок   | GitHub Actions после загрузки в `drawn/`                        | Рисующему не нужны Python и OpenCV: загрузил — через пару минут на сайте                                                |
| Где хранить          | Рабочие файлы — `art/<id>/`, спрайт — рядом с моделью           | В сборку попадает только спрайт; каркас, запрос и исходники остаются для истории и повторов                             |
| Фото                 | Свои и со свободной лицензией — в `photos/`, остальное — ссылки | Репозиторий публичный                                                                                                   |
| Размер спрайта       | До 16 px/м, WebP                                                | Больше на карте не видно; 50–300 КБ на здание                                                                           |
| Модель после рисунка | Остаётся                                                        | Силуэт, тень, детализация, замена рисунка; без загруженной картинки — запасной вид                                      |

## Ограничения и что дальше

- Камера одна (с юга): здания с главным фасадом на север видны с тыла — как и раньше у
  моделей. В запросе это оговорено.
- Генератор может нарисовать здание чуть иначе по форме (лишний этаж, другой изгиб); ECC
  исправит только сдвиг и масштаб. Смотрите `check.jpg`; неудачный рисунок — перерисовать.
- Масштаб рисунков разный (зависит от размера здания), поэтому толщина контуров у маленьких и
  больших зданий немного разная. Если будет заметно — ставить общий ppm для группы зданий.
- Сотни зданий: рисунки нужно грузить по видимости и иметь уменьшенные копии для мелкого
  масштаба; общий стиль держать образцом в каждом запросе.
- Генерацию можно автоматизировать через API (OpenAI Images, Gemini и др.) тем же запросом
  и каркасом — нужен ключ API в секретах репозитория.
