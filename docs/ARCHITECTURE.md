# Архитектура

Текущее состояние — каркас. Решения ниже приняты как разумные значения по умолчанию и могут
быть пересмотрены (см. [QUESTIONS.md](QUESTIONS.md)).

## Стек

- **TypeScript** (strict) + **Vite** — сборка статического сайта без сервера.
- **Vitest** — модульные тесты, **Prettier** — форматирование.
- Хостинг — **GitHub Pages**, сборка и публикация — **GitHub Actions**.
- Карта — собственный движок на **Canvas 2D** (`src/map/`, см. [MAP.md](MAP.md)); данные — из
  OpenStreetMap (скрипт `scripts/map/osm_tool.py`, Python); облик зданий — рисунки по
  каркасу (`scripts/art/`, см. [ART.md](ART.md)).
- UI-фреймворк пока не выбран.

## Слои

```
src/
  core/   — симуляция: состояние, действия, правила, RNG. Без DOM и без браузерных API.
  map/    — движок карты: проекция, данные (data/), модели объектов, отрисовка, жесты.
  ui/     — экраны и панели.
  main.ts — точка входа: связывает core и ui, игровой цикл.
public/   — статические файлы как есть (картинки, данные, прототип).
tests/    — тесты.
```

Принципы ядра:

1. **Состояние — сериализуемые данные** (`GameState`): только JSON-совместимые значения.
   Сохранения, отладка, реплеи и (в будущем) мультиплеер получаются почти даром.
2. **Изменения — только через действия**: `applyAction(state, action) → newState`.
   UI не меняет состояние напрямую.
3. **Детерминизм**: вся случайность через `core/rng.ts` с seed, хранящимся в состоянии.
   Никакого `Math.random()` и `Date.now()` внутри `core/`.
4. **Данные отдельно от кода**: баланс (бригады, аварии, здания, районы) — в таблицах/JSON,
   чтобы его мог править геймдизайнер.

## Сборка и публикация

Работаем в одной ветке `main`. Каждый push в неё публикуется автоматически:

- игра: https://alexkof.github.io/ekbgame/
- прототип: https://alexkof.github.io/ekbgame/prototype/

Workflow [`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml): `npm ci` →
`npm run check` (формат, типы, тесты) → `npm run build` → публикация `dist/` через
`actions/deploy-pages`. Если проверки не прошли, сайт не обновляется.

Внизу страницы показаны коммит и время сборки — видно, какая версия открыта.

Рисунки зданий: workflow [`.github/workflows/art.yml`](../.github/workflows/art.yml) запускается,
когда в `art/<id>/drawn/` загружен рисунок, ставит его на карту (`scripts/art/art.py import
--new`), коммитит результат в `main` и запускает публикацию (см. [ART.md](ART.md)).

### Однократная настройка

Settings → Pages → Build and deployment → Source: **GitHub Actions**. Репозиторий должен
оставаться публичным: на бесплатном плане GitHub Pages работает только для публичных.
